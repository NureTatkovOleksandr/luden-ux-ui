## Формат і стиль

- Desktop: 15 кадрів **1440 × 900**, сторінка `Page 1`.
- `Luden — Компоненти`: 31 компонент — поля, кнопки, картки восьми ігор, шапки, фільтри. У кадрах використано їхні екземпляри.
- Світлі поверхні й червоний акцент Luden. Основні кольори в оглянутих S-01/S-02-A: #B93838, #FFFFFF, #E9ECEF, #212529, #6C757D. У деталях «До кошика» синя. Це опис оформлення, не повна система токенів.
- Текст — Inter, логотип — Jaro. У вході й реєстрації ліворуч чорне поле з кольоровим орнаментом; у каталозі кольорові обкладинки.
- M-01, M-02, M-02-E, M-03, M-03-E візуально є діалогами на затемненому каталозі. Технічно це повнорозмірні кадри з NAVIGATE, а не OPEN_OVERLAY.

## Дані й тексти

Головна гра — **Cyberpunk 2077**, **$24.99 USD**, кількість **1**. Ціна узгоджена в каталозі, деталях, кошику й оплаті; бібліотека після підтвердження містить ту саму назву. Значення є даними макета, а не актуальною пропозицією продажу.

| Гра | Ціна в макеті |
| --- | ---: |
| Cyberpunk 2077 | $24.99 |
| Hollow Knight: Silksong | $19.99 |
| PEAK | $7.99 |
| Hades II | $29.99 |
| Stardew Valley | $14.99 |
| Hollow Knight | $14.99 |
| Celeste | $19.99 |
| Balatro | $14.99 |

Позитивний пошук: `Cyberpunk 2077`, одна картка. Порожній: `zz-no-match`, «Нічого не знайдено», «Очистити пошук». Помилка каталогу має окремі заголовок і кнопку «Спробувати ще раз».

Порожній кошик показує $0.00 і кнопку без переходу. До сплати за одну гру — $24.99 USD, бонуси — 0. Повідомлення оплати прямо вказують, що кошти не списуються. Вимога появи гри лише після успішної оплати зберігається; макет показує підготовлений результат.

Позначку −50% слід доповнити базовою ціною або прибрати. «Щонайменше 8 символів» потребує рішення Q-11, узгодженого з API. Рекомендований текст порожньої бібліотеки: «Придбані ігри з’являться тут після успішної оплати».

## Налаштована навігація

```text
S-01 ↔ S-01-R
S-01 / S-01-R → S-03-A → S-02-A → M-01 → M-02 → M-03 → S-03-B
S-02-A → S-02-R → S-02-B → S-02-A
S-02-R ─ Очистити → S-02-A
M-02 ─ Видалити → M-02-E ─ Закрити → S-02-A
M-03 / M-03-E ─ Скасувати → M-02
M-03-E ─ Спробувати ще раз → M-03
S-02-C ─ Спробувати ще раз → S-02-A
S-03-B → S-02-P → S-02-RP ─ Очистити → S-02-P
```

Початкові потоки: **«Покупка гри»** (S-01), **«Відмова оплати»** (M-03-E), **«Помилка каталогу»** (S-02-C). Пошук показує готові стани по кліку на поле. «До кошика» відкриває кошик одразу. Повні зв’язки, включно з проблемними поверненнями після покупки, наведено в [карті екранів](../02_architecture/02_Screen_Map.md).

## Макет для повторної перевірки

Робоче завдання від 2026-11-20, очікує погодження. Ціль — desktop 1440 × 900. Зберегти навігацію та ідентифікатори наявних кадрів, де це можливо. Для навчального приймання підготувати grayscale low-fidelity варіант або записати погодження на кольоровий формат. [P-08](../01_requirements/Decision_Log.md#рішення-на-погодження)

Додати в Present окремі стартові сценарії для помилок форм, відмови оплати та помилки каталогу. Для основного маршруту використати готові демонстраційні дані. Для перевірки очікування показати індикатори завантаження та обробки. У порожній бібліотеці зазначити «Придбані ігри з’являться тут після успішної оплати». Позначку −50% прибрати до підтвердження базової ціни.

У покупецькому макеті прибрати елементи Google, відновлення, обраного, списання бонусів, перемикачі мови, валюти й теми та дії сортування, знижок і вкладки замовлень, доки їхня поведінка поза обсягом приймання. Показувати валюту як значення. Операції провайдера, серверну автентифікацію, видачу ліцензії та Admin перевірити на рівні застосунку.

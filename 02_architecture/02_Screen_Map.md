# Карта екранів Luden

**G2 · Чернетка.** Канонічна поверхня має один ID, а різні стани тієї самої поверхні позначаються суфіксом. Модальні вікна M-01…M-03 відкриваються поверх каталогу.

| ID | Поверхня або стан | Як потрапити | Куди можна перейти |
| --- | --- | --- | --- |
| S-01 | Вхід за паролем | Початок основного потоку | Реєстрація, профіль або помилка на тій самій формі |
| S-01-R | Реєстрація | Посилання з входу | Профіль після успішної реєстрації та автоматичного входу. У разі відмови показується повідомлення |
| S-02-A | Каталог з результатами | Навігація з профілю | Пошук, деталі, кошик |
| S-02-B | Немає збігів | Пошук за відсутньою назвою | Очистити запит і повернутися до каталогу |
| S-02-C | Помилка завантаження | Приклад невдалого запиту | Повернення через навігацію або повторне відкриття каталогу |
| M-01 | Деталі гри | Вибір картки з результатів | Додати гру, закрити деталі |
| M-02 | Кошик | Відкрити кошик після додавання | Зміна кількості, видалення, оформлення, закриття |
| M-03 | Оплата | Дія оформлення у непорожньому кошику | Відміна, приклад помилки або підготовлений результат |
| S-03-A | Профіль з порожньою бібліотекою | Після входу у демопрофіль без покупок | Каталог |
| S-03-B | Профіль з придбаною грою | Підготовлений результат симуляції оплати | Перегляд бібліотеки, повернення до каталогу |

Завантаження каталогу, помилку входу, порожній кошик і відмову оплати показати у довідкових прикладах станів. Окремий макет адміністратора залежить від Q-05.

## Основний маршрут

```text
S-01 → S-03-A → S-02-A → M-01 → M-02 → M-03 → S-03-B
                      ↘ S-02-B → S-02-A
```

Перехід M-03 → S-03-B у Figma веде до підготовленого результату. У продукті доступ до гри визначає стан замовлення. Гілки реєстрації, помилки й порожнього кошика описані в [контрактах](03_Screen_Contracts.md).

# Карта екранів Luden

**G2 · редакція 2026-11-07.** Актуальний дизайн Figma описано нижче. Окрема карта HTML зберігає попередні переходи, щоб не змішувати різні реалізації.

## Карта Figma

Усі 15 кадрів і node ID наведено в [брифі](../03_figma_prep/05_Figma_Brief_v0.1.md). Джерело зв’язків — [інвентар](../04_design/Figma_Prototype_Inventory.json), зріз 2026-11-07.

| Група | Налаштовані переходи |
| --- | --- |
| Вхід | S-01 ↔ S-01-R; обидві основні кнопки → S-03-A |
| Покупка | S-03-A → S-02-A → M-01 → M-02 → M-03 → S-03-B |
| Пошук до покупки | S-02-A → S-02-R → S-02-B; очищення R/B → S-02-A |
| Кошик | Видалення → M-02-E; закриття M-01/M-02/M-02-E → S-02-A |
| Оплата | Скасування M-03/M-03-E → M-02; повтор M-03-E → M-03 |
| Після покупки | S-03-B → S-02-P → S-02-RP; очищення RP → P; «Моя бібліотека» з P/RP → S-03-B |
| Помилки | Окремі стартові потоки M-03-E та S-02-C; повтор каталогу → S-02-A |

У Figma «До кошика» відразу відкриває M-02, пошук змінює кадри по кліку, а діалоги використовують NAVIGATE. Вибір жанру, зміна кількості, processing, помилка входу й завантаження не налаштовані. Гостьового стартового потоку немає.

S-02-P/S-02-RP відкривають спільний M-01, що закривається в S-02-A. S-02-RP також веде до спільного S-02-B, звідки очищення повертає S-02-A. Це втрачає стан покупки й пошуку; зауваження F-01 відкрите.

| ID | Поверхня / стан | Вхід | Вихід |

| S-01-R | Реєстрація | Посилання з S-01 | S-01 або профіль після валідного подання; помилка збігу лишає форму |
| S-02-A | Каталог | «Магазин» із профілю | Пошук і жанр, деталі, кошик, профіль |

| S-02-C | Помилка каталогу | Кнопка «Помилка каталогу» у довідці станів | «Спробувати ще раз» повертає локальний список за активними фільтрами |

## Довідкові стани

| Експорт | Стан / спосіб відкриття |
| --- | --- |
| REF-01_login_error | Помилковий пароль на S-01 |
| REF-02_catalog_loading | «Завантаження» у довідці; у DOM має ID S-02-L. Автоматичне завершення запиту не моделюється |
| REF-03_cart_empty | Порожній M-02 після видалення позицій або кнопка «Порожній кошик» |
| REF-04_payment_declined | «Відмова оплати» відкриває M-03 з повідомленням і однією Atlas Drift. Це підготовка стану, а не результат відхиленого запиту |

REF — ім’я експорту, не окрема продуктова сторінка. Службові кнопки можуть змінювати дані й не замінюють гостьовий маршрут або тест прав.

## Основний маршрут

```text
S-01 → S-03-A → S-02-A → M-01 → S-02-A → M-02 → M-03 → S-03-B
  ↕                       ↕                 ↑      |
S-01-R                  S-02-B              └──────┘ скасування
```

Додавання гри закриває деталі; кошик відкривається окремою дією. M-01…M-03 відображаються поверх каталогу. Закриття деталей і кошика зберігає пошуковий контекст. Закриття оплати повертає в кошик; під час обробки закриття й повторне підтвердження заблоковані.

## Межі покриття

US-03 вимагає публічного каталогу. Цільовий гостьовий сценарій продукту — відкриття каталогу без входу, перегляд результатів і деталей; захищені дії потребують автентифікації. Звичайної гостьової навігації та повернення після входу у поточному прототипі немає. Цей сценарій не має статусу PASS.

Прототип не має серверної сесії, ролей чи статусів замовлення. Перехід після реєстрації описаний у D-08; поведінка реального застосунку залежить від Q-09. [Контракти](03_Screen_Contracts.md) визначають контроли, вимоги та рівні доказів.
